Evolution Feedback

Each evolution appraisal gets written feedback in your repository. This protocol explains the steps, what the feedback file contains, and how to use it in the next appraisal.

The steps

Each step leaves a file in your repository, and every file stays there. The student commits the student's files. The professor commits only the feedback files, in feedback/.

StepWho actsWhat they doFile left in your repositoryWhen
1StudentCommit the appraisal as the README of its evolution folder, and submit the repository URL and a PDF in WTClass.evolution-N/README.mdBy the due date posted in WTClass
2ProfessorRead the appraisal and the artifacts it cites, and commit feedback written to you.feedback/evolution-N.mdAfter the due date
3ProfessorEnter the score in WTClass.None (the score is in WTClass)With the feedback
4StudentRead the feedback and carry its question into the next appraisal.The next evolution-N/README.mdBefore the next due date

What the feedback file contains

  1. What is working, with the evidence that shows it.
  2. What needs attention, as specific, checkable items.
  3. How ready your integration thinking is for the capstone.
  4. One question to carry into the next appraisal.

The score is in WTClass, not in the file. The file is about the work.

Using the feedback

The question at the end of each feedback file is meant to be answered in the next appraisal, not in a reply. An appraisal that takes up the question shows growth from one evolution to the next, which is what the integration dimension of the rubric looks for. The feedback files stay in your repository, so by the proposal you have four of them, and they are a record of how your thinking about the four areas developed.

Files that are mine

The feedback/ folder holds only my files. Do not edit, move, or delete them. Everything else in the repository is yours.

Dates, submission steps, and scoring are on the WTClass pages. What an appraisal must argue is in the portfolio guide.

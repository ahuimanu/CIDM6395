Systems Development (SS)

Systems Development builds the software that runs. It is the one area that every prototype must include.

Software that someone else can run

SS designs and builds the software that turns the work of the other areas into a system: the program that loads the data, the application a user opens, the job that runs on a schedule, and the tests that show it works. Software counts as SS work in the capstone when someone other than its author can start it and use it.

I require SS in every prototype because the prototype has to run, and software is the part that runs. That requirement does not place SS at the center of the design. In the example project on this site, SS appears twice, loading the data at the start of the flow and delivering the result at the end, while DM and BA do the work in between; the chain view in Figure 02 shows the arrangement.

What to show in your repository

SS is the code I start when I follow your README. In the repository, show the Python source, a requirements.txt, a README that starts the prototype in a fresh clone, and tests where you have them. The prototype guide gives the rules for how the prototype runs.

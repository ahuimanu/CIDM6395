Data Analytics (BA)

Data Analytics is the area that answers the question in your pretext. It takes data that DM has prepared and turns it into something a person can act on.

In a working system

BA produces findings: a rate, a forecast, a classification, a comparison, a chart that makes a pattern visible. In the example project used across this site, BA computes complaints per thousand loans for each lender and flags the ones that stand out, and that flag is what the examiner acts on. A system without BA can store and move data, but it cannot answer anything about it.

BA leans on the other areas at both ends. Its input has to arrive in a known shape, which is DM's job. Its output reaches a user only through software, which is SS. And when the data or the result is confidential, CN decides who sees it. In your prototype

BA is usually the step that produces what the user acts on. The proposal test is simple: take BA away and the user gets data but no answer. In the repository, BA should appear as code that computes the result (a script, or a notebook the pipeline calls), not as a chart pasted into the paper.

Data Analytics (BA)

Data Analytics turns managed data into a claim that someone can act on. In the capstone it is the area that answers the question in your pretext.

What BA does in a working system

BA takes prepared data and produces a finding: a rate, a forecast, a classification, a comparison, a visualization. Its output is a claim that a person can act on, such as which lenders to review first. Without BA, a system can store and move data, but it cannot answer a question about it.

BA depends on the other areas at both ends. It needs data in a known shape, which DM provides. Its result reaches a user only through software, which SS provides. And its data or its result may be confidential, which CN governs.

Where BA meets the other areas

In Figure 01, BA overlaps each of the other three areas, and each overlap is a recognizable practice:

  • BA with DM: the data pipeline. Managed data prepared for analysis.
  • BA with SS: decision delivery. Analysis delivered to a user through software.
  • BA with CN: security analytics. Analysis of security data, or analysis under a privacy constraint.

BA in the prototype

In a prototype, BA is usually the step that produces the output the user acts on. Its test in the proposal is direct: remove BA, and the user receives data but no answer. Show BA in the repository as code that computes the result (a script or a notebook the pipeline calls), not as a chart pasted into the paper.

Your repository

Everything you hand in for the capstone is a file in your private repository in the course organization, at a path set below. I evaluate the repository as it stands at the commit made by the deadline.

The required files

Use these paths and names exactly, capitalization included. Where the tree offers two names, pick one. Because every repository has the same layout, I can check each one the same way, opening each required path in turn. A file at another path or under another name is misplaced and costs organization points even when I find it. A file I cannot find is missing.

your-repository/
├── README.md                     the front door: what is here and where
├── portfolio/
│   ├── BIO.md                    your professional bio
│   ├── inventory/README.md       your skills inventory (Evolution 0)
│   ├── BA/README.md              your final appraisal, with the work it cites
│   ├── DM/README.md
│   ├── SS/README.md
│   └── CN/README.md
├── proposal/
│   ├── proposal.md               nine sections, at most two pages of text
│   ├── diagram.png               your drawing of the project (or diagram.svg)
│   └── consultation-response.md
├── prototype/
│   ├── README.md                 areas, Python version, data, run command, provenance
│   ├── requirements.txt
│   ├── data/                     the data, or a script that retrieves it
│   └── ...                       Python source, notebooks, tests
├── deliverables/
│   ├── synthesis-paper.pdf       5 to 10 pages (or synthesis-paper.md)
│   ├── slides.pptx
│   └── video.mp4                 or video-link.md
└── feedback/                     the professor's files only
    ├── evolution-N.md
    ├── proposal.md
    └── final-project.md

Everything outside feedback/ is yours to write. The feedback/ folder holds only my files; leave them where they are and do not edit them. Each deliverable's guide explains what goes in its files: the portfolio and bio, the proposal, the synthesis prototype, the paper, and the presentation.

Moving the evolution folders

You committed each evolution to a top-level evolution-N folder. Before the final commit, move them into portfolio/ with git mv, which carries each file's history along:

Move this folderTo this path
evolution-0/portfolio/inventory/
evolution-1/portfolio/BA/
evolution-2/portfolio/DM/
evolution-3/portfolio/SS/
evolution-4/portfolio/CN/

The root README

A reader should reach every deliverable in one click from README.md. Say briefly what the portfolio and the project are, link to each required file and folder, and record which AI tools you used and for what (or link to the place in prototype/README.md where you do). If the project changed after the proposal, say what changed and why.

Before the final commit

The work itself has to be in the repository; a link to another repository or a cloud drive can sit next to it but does not replace it. Only the file at the required path counts, so move drafts and old versions out of the way or delete them. And check the whole commit history, not just the latest commit, for credentials, API keys, and private data.

The WTClass page "Your Course Repository: Required Structure" gives the same list of required files.

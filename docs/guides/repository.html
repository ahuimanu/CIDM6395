Your Repository

Every capstone deliverable is a file you leave in your course repository. This guide shows the structure, which folder holds each deliverable, and who writes each file.

One repository, two jobs

Your repository in the course GitHub organization is where you turn in every piece of the capstone, and it is the portfolio you show after the course ends. Every deliverable is a file in it. Nothing outside it counts unless the repository links to it clearly, and I evaluate it at the commit that exists at the deadline.

The structure

Folder names can vary. Their functions cannot. If you use different names, say so in the root README.

your-repository/
├── README.md                  the front door: what is here and where
├── BIO.md                     your professional bio
├── evolution-0/README.md      the skills inventory
├── BA/                        one folder per area: README, final appraisal,
├── DM/                          and the work the appraisal cites
├── SS/
├── CN/
├── proposal/
│   ├── proposal.md            nine sections, at most two pages of text
│   ├── diagram.png            your drawing of the project (or .svg)
│   └── consultation-response.md
├── prototype/
│   ├── README.md              areas, Python version, data, run command, provenance
│   ├── requirements.txt
│   ├── data/                  the data, or a script that retrieves it
│   └── ...                    Python source, notebooks, tests
├── deliverables/
│   ├── synthesis-paper.pdf    5 to 10 pages (or .md)
│   ├── slides.pptx
│   └── video-link.md          or the video file
└── feedback/                  the professor's files only
    ├── evolution-N.md
    ├── proposal.md
    └── final-project.md

The feedback/ folder holds only my files. Do not edit, move, or delete them. Everything else in the repository is yours.

The root README

The root README is the front door. A reader should reach every deliverable in one click from it. It states what the portfolio contains, links to BIO.md, and gives the location of the four area folders, the proposal, the prototype, the paper, the slides, and the video. It also records which AI tools you used and for what (or points to the prototype README for this), and, if the project changed after the proposal, what changed and why.

Three rules

  1. Work is a file, not a link. A link to another repository or a cloud drive can supplement the work. It does not replace it.
  2. One final version. If more than one version of a file exists, name the final one or point to it from the README. If I have to guess, the guess costs organization points.
  3. No secrets. No credentials, API keys, or private data anywhere in the commit history.

The WTClass page "Your Course Repository: Required Structure" lists the folder names I recognize without a note.

Your repository

Everything you submit for the capstone is a file in your private repository in the course organization, at a path fixed in the list below. I evaluate the repository as it stands at your last commit before the deadline, so that commit is your submission.

The required files

Use these paths and names exactly, capitalization included; where the tree offers two names, use one of them. I ask for exact paths so that I can check every repository in the same way, opening each required path in turn. A file at another path or under another name is therefore misplaced, and it costs organization points even when I find it. A file I cannot find is missing.

You write everything outside feedback/. That folder holds only the feedback files I commit, and you should leave them where they are without editing them, since they are the record of what I told you. Each deliverable's guide explains what goes in its files: the portfolio and bio, the proposal, the synthesis prototype, the paper, and the presentation.

Moving the evolution folders

During the term you committed each evolution to a top-level evolution-N folder, and before the final commit you move them into portfolio/ as the table shows. Use git mv for the move, because it keeps each file's history attached to the file.

The root README

The root README.md is the first file a reader opens, so it should let them reach every deliverable in one click. Say briefly what the portfolio and the project are, link to each required file and folder, and record which AI tools you used and for what (or link to the place in prototype/README.md where you record them). If the project changed after the proposal, say what changed and why.

Before the final commit

The work itself has to be in the repository; a link to another repository or a cloud drive can sit next to it but does not replace it, because a link may change after the deadline. Only the file at the required path counts, so move drafts and old versions out of the way or delete them. Finally, search the whole commit history for credentials, API keys, and private data, since anything committed at any point remains readable in the history after you delete it from the current files.

The WTClass page "Your Course Repository: Required Structure" gives the same list of required files.

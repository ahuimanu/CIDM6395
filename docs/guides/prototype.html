Guide · The synthesis prototype

The synthesis prototype

The synthesis prototype is the working part of your capstone, the part you build and deliver this term. It is a time-bounded slice of a larger project, built as a minimum viable product, and at the end of the term I run it on real data by following your README.

The full project and the prototype

Your proposal describes two projects. As used in this course, the full project is what one competent person could build in about a year of full-time work, and it has to need all four areas, since a project that one area could finish alone would not test synthesis. The synthesis prototype is the part of the full project that you can finish in the weeks after your proposal is approved.

The prototype is a sample of the full project, not a smaller project of its own. It carries real data along one complete path, from the source to something a user sees and acts on, through SS and at least two of BA, DM, and CN. Each step on that path may do much less than it would in the full project, provided that it runs. A prototype with one area built well and the others left as stubs does not meet this test, and neither does one with every component built halfway, because in both cases there is no path I can follow from the data to the result.

Which areas count

An area counts when the prototype breaks without it. I require SS because the prototype has to run, and SS is the area that builds what runs. Beyond SS, the prototype integrates at least two of the other three areas. The four conditions on data

I hold the prototype's data to four conditions, each of which protects a different part of the case the prototype makes.

The first is relevance. The data come from the domain of your problem, and every field you use connects to a decision or an operation in that domain. A dataset chosen because it was easy to download, with a problem invented afterward to fit it, does not meet this condition.

The second is accountability. Someone outside the course answers for the original data: a government agency, a firm, a research group, or your employer with written permission. Your README carries a provenance table that records who produced the data, the terms under which you use it, the date you obtained it, and each change you made to it, because a claim drawn from data that no one answers for cannot be checked.

The third is availability. I have to be able to obtain the same data you used, so the repository holds either the data or a script that retrieves it from the source.

The fourth is quality, which in this course means transactional variety: many records, of more than one kind, produced by real activity over time and carrying the gaps, duplicates, and late corrections that real activity leaves. Data with these defects are acceptable, since cleaning them is part of the DM work. A single clean table of a few hundred rows is not acceptable, because it leaves DM with nothing to do.

Sample datasets

The datasets on Kaggle and the UCI repository, and those that come with textbooks, are useful for learning a technique, but they make weak material for a capstone. In most of them someone else has already framed the problem and done the cleaning. The file is a frozen snapshot, so SS has nothing to ingest and CN has nothing to protect. The source is often an uncited copy of another organization's data. And because thousands of public notebooks use the same file, I cannot tell which decisions in your work are yours.

Government and transactional data usually meet all four conditions. An agency stands behind the data and publishes a data dictionary, and event-level records such as flights, loan applications, complaints, and payments give every area real work. An aggregate series from the Federal Reserve or the BEA is also better evidence than most sample datasets, since an agency answers for every value in it, though it works best as context joined to an event source. The WTClass page "Data Sources for the Capstone" lists 40 sources I have checked.

You may use synthetic data if you generate it from a documented real reference, commit the generator, and use the result only to supplement real data or to stand in for data that you can show you cannot obtain. Without a real reference, the patterns an analysis finds in synthetic data are the ones the generator put there, so they say nothing about the domain.

How it runs

Write the prototype in Python. Its interface can be a command-line program, a web application (Streamlit, for example), or a Jupyter notebook; a notebook should call the data layer, the pipeline, and the controls rather than contain them.

I do not accept a prototype built only in Excel, and I discourage macros, for three reasons: Excel does not run on Linux, a macro written on Windows often fails on a Mac, and Git cannot show me what changed inside a macro workbook. Any tool other than Python needs my approval in the proposal cycle, and I approve only tools that run on Windows, macOS, and Linux.

At review I clone your repository into an empty folder and follow prototype/README.md from the first step. If a step needs something only you have, such as a personal API key, I record it and ask you to run the prototype for me in the debrief, for at least five minutes.
